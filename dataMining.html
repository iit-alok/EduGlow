Module 01

1. KDD Process & Core Foundations

Knowledge Discovery in Databases (KDD) is the comprehensive process of converting raw transactional data into actionable business intelligence. Data mining serves as the computational pattern-extraction core within this iterative system.

The 7 Stages of KDD:
  1. Data Cleaning: Removes noise, inconsistent codes, and missing values.
  2. Data Integration: Merges multiple heterogeneous sources (SQL, CSVs, API feeds).
  3. Data Selection: Retrieves task-relevant subsets from the warehouse.
  4. Data Transformation: Normalizes or aggregates data into analysis-ready formats.
  5. Data Mining: Applies intelligent algorithms to uncover latent patterns.
  6. Pattern Evaluation: Identifies truly interesting rules based on objective metrics.
  7. Knowledge Presentation: Uses charts and dashboards to convey insights.

2. 3-Tier DW Architecture & OLAP Operations

Enterprise data warehouses decouple analytical reporting queries from online transactional engines to avoid locking production databases.

Dimension OLTP (Transactional) OLAP (Analytical)
Primary Users Clerks, DBAs, frontline applications Business Analysts, Managers, Data Scientists
Data Content Current, detailed, highly normalized snapshots Historical, consolidated, multi-year summaries
Workload High-velocity ACID writes and updates Complex, read-heavy analytical aggregations
Core Multidimensional OLAP Cube Operations:
  • Roll-up: Navigates from fine granularities to summary aggregations (e.g., City → Country).
  • Drill-down: Reverses roll-up; breaks broad concepts down into deeper granular units (e.g., Year → Quarter → Month).
  • Slice: Selects a single dimension value to extract a 2D rectangular sheet.
  • Dice: Selects specific sub-ranges across two or more dimensions to form a new sub-cube.

3. Multidimensional Schema Design

Data warehouses organize metrics inside centralized Fact Tables surrounded by descriptive Dimension Tables:

Star Schema

Features one central Fact Table surrounded by denormalized Dimension Tables. Optimized for query simplicity and fewer SQL table joins.

Snowflake Schema

Normalizes outer dimension tables into hierarchical sub-tables. Minimizes disk storage and redundancy at the cost of more join operations.

4. Data Preprocessing Pipeline

Real-world records suffer from noise, missing attributes, and conflicting units. Smoothing data via binning techniques cleans signals before training algorithms. 

// Java simulation of smoothing noisy warehouse values via Bin Means
public class DataPreprocessing {
    public static double[] smoothByBinMeans(double[] rawData, int binSize) {
        double[] smoothed = new double[rawData.length];
        for (int i = 0; i < rawData.length; i += binSize) {
            double sum = 0;
            for (int j = i; j < i + binSize && j < rawData.length; j++) {
                sum += rawData[j];
            }
            double mean = sum / binSize;
            for (int j = i; j < i + binSize && j < rawData.length; j++) {
                smoothed[j] = mean;
            }
        }
        return smoothed;
    }
}

5. Association Rules & Apriori Algorithm

Frequently utilized in Retail Market Basket Analysis to spot customer purchasing tendencies. Rules are expressed as: $\{A\} \Rightarrow \{B\}$.

Support ($S$)

Fraction of total transactions that contain both itemsets $A$ and $B$.

Formula: $P(A \cup B)$
Confidence ($C$)

Probability that transaction $B$ is purchased given that itemset $A$ is present.

Formula: $P(B | A) = S(A \cup B) / S(A)$
The Apriori Downward-Closure Property:

Any subset of a frequent itemset must also be frequent. Conversely, if an itemset is infrequent, all of its supersets are pruned immediately.

7. Cluster Analysis (K-Means Clustering)

An unsupervised machine learning method that groups records according to shared Euclidean distance attributes.

Step-by-Step Algorithm:
  1. Randomly initialize $K$ centroids within the feature space.
  2. Compute Euclidean distance between each data point and all centroids.
  3. Assign each data point to its closest centroid.
  4. Recalculate centroid coordinates as the arithmetic mean of all cluster members.
  5. Repeat steps 2 through 4 until cluster memberships stop shifting.

8. Placement & University Examination Cheatsheet

OLTP (Online Transaction Processing) handles day-to-day high-throughput operational insert/update queries (e.g., ATM withdrawals, order purchases). OLAP (Online Analytical Processing) handles read-intensive historical queries across multidimensional cubes for strategic executive decision support.

A Data Warehouse is a centralized database containing consolidated, enterprise-wide historical records spanning all departments. A Data Mart is a smaller, departmental slice tailored exclusively for one division (such as Sales, Accounting, or Marketing).
