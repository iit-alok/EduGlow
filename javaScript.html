Module 01

1. Single-Threaded Runtime & The Non-Blocking Dilemma

JavaScript is a single-threaded language [source: 7, 10]. It possesses a single Call Stack, meaning it can only execute one instruction at a time in a synchronous, top-to-bottom sequence [source: 5, 10].

The Danger of Blocking the Main Thread

If network HTTP requests, image rendering, or file parsing were executed synchronously, the browser execution thread would freeze completely, locking UI scrolling, button clicks, and tab interactions [source: 3, 9]. Asynchronous programming allows long operations to run in the background while the UI remains responsive [source: 1, 3].

2. The Event Loop, Web APIs & Task Queues

How does JavaScript perform asynchronous tasks with only one thread? The browser provides Web APIs (C++ background worker threads for timers, network sockets, DOM events) that manage operations outside the JavaScript execution thread [source: 9, 10].

Component Queue Priority What Operates Here
Call Stack Immediate Synchronous code frames (Last-In, First-Out) [source: 10]
Microtask Queue High Priority Promise.then(), catch(), queueMicrotask() [source: 10]
Macrotask Queue Standard Priority setTimeout, setInterval, I/O callbacks, setImmediate [source: 10]

3. Callbacks & Callback Hell (The Pyramid of Doom)

A Callback is a function passed as an argument to another function, scheduled to execute once an asynchronous task completes [source: 7]. Chaining multiple sequential requests leads to deeply nested indentation known as "Callback Hell" [source: 7, 8]: 

// Callback Hell: Fragile error propagation & poor maintainability [source: 7, 8]
getUserData(userId, (user) => {
    getUserOrders(user.id, (orders) => {
        getOrderInvoice(orders[0].id, (invoice) => {
            generatePDF(invoice, (pdf) => {
                console.log("PDF rendered successfully");
            });
        });
    });
});

4. ES6 Promises: Architecture & Lifecycle

A Promise is an object representing the eventual completion (or failure) of an asynchronous operation [source: 7, 8]. It exists in one of three distinct, immutable states [source: 7, 8]:

1. Pending

Initial state; operation still running [source: 7, 8].

2. Fulfilled

Operation resolved successfully [source: 7, 8].

3. Rejected

Operation encountered an error [source: 7, 8]. 

// Creating a custom Promise [source: 5, 8]
const fetchStudentScores = (studentId) => {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            if (studentId) {
                resolve({ id: studentId, author: "Alok Rajpoot", score: 98 });
            } else {
                reject(new Error("Invalid Student Identifier provided"));
            }
        }, 1000);
    });
};

// Chaining with .then(), .catch(), and .finally() [source: 4, 7]
fetchStudentScores(101)
    .then(data => console.log("Fetched:", data))
    .catch(err => console.error("Error caught:", err.message))
    .finally(() => console.log("Operation complete"));

5. Modern Async / Await Syntactic Sugar

Introduced in ECMAScript 2017 (ES8), async / await is syntactic sugar built on top of Promises [source: 7, 8]. It enables developers to structure asynchronous logic in a clean, sequential, synchronous-looking format without nested callbacks [source: 4, 8]. 

// Elegant asynchronous flow with structured error handling [source: 4, 7]
async function loadEduGlowNotes() {
    try {
        const response = await fetch("/api/notes"); // Pauses function execution until resolved [source: 4, 5]
        if (!response.ok) {
            throw new Error(`HTTP Failure status: ${response.status}`);
        }
        const notes = await response.json();
        console.log("Notes retrieved:", notes);
        return notes;
    } catch (error) {
        console.error("Diagnostic Trace:", error.message);
    }
}

6. Native Fetch API vs. Axios HTTP Client

Web applications make HTTP requests using either browser-native fetch() or third-party libraries like Axios [source: 1, 6].

HTTP Error Codes Resolves 404/500 as fulfilled (checks `res.ok`) [source: 6] Rejects automatically on 4xx / 5xx codes [source: 6]

7. Parallel Execution & Promise Combinators

Never execute independent HTTP requests sequentially using consecutive await lines. Use Promise Combinators to execute operations in parallel [source: 8, 10]:

Promise.all([p1, p2])

Runs in parallel. Resolves only when all promises succeed; rejects immediately if any single promise fails [source: 8, 10].

Promise.allSettled([p1, p2])

Runs in parallel and never short-circuits. Returns the resolution or rejection status for each request once all are settled.

Promise.race([p1, p2])

Settles as soon as the fastest promise finishes (whether it resolves or rejects).

Promise.any([p1, p2])

Resolves as soon as the first successful promise finishes. Ignores rejections unless all promises fail.

8. Top Technical Placement Interview Questions

setTimeout(fn, 0) registers a macrotask in the Host Web API environment [source: 10]. Even with zero delay, its callback is placed into the Macrotask Queue [source: 10]. The Event Loop cannot run this callback until the synchronous Call Stack is completely empty and all pending Microtasks have been processed [source: 10].

Microtasks (e.g., Promise.then(), catch(), queueMicrotask()) have higher execution priority than Macrotasks (e.g., setTimeout, setInterval) [source: 10]. The Event Loop processes the entire microtask queue right after the Call Stack empties, before processing the next macrotask or updating browser rendering frames [source: 10].
